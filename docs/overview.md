# Как устроена система

> Есть видео на 3 минуты с теми же пояснениями: [смотреть в браузере](https://jojoba-2029.github.io/CRM-demo/media/demo.mp4).

**Что это.** Веб-приложение, где руководитель (постановщик) заводит стройки и ставит по ним задачи, а исполнители берут задачи в работу и сдают на проверку. Постановщик принимает работу или возвращает её на доработку с комментарием. Каждая смена статуса записывается в историю: кто, когда и что изменил.

**Из чего состоит.** Две части. _Интерфейс_ — страницы, которые открываются в браузере. _База данных_ — хранилище, где лежат объекты, задачи и история. База находится в облачном сервисе Supabase; там же проверяются логин и пароль.

**Как защищены данные.** Главное правило: проверки сделаны в самой базе, а не только в интерфейсе. Интерфейс просто не показывает лишние кнопки. Но даже если кто-то обойдёт интерфейс и обратится к базе напрямую (это технически возможно для любого веб-приложения), база сама ответит отказом.

- **Вход только по выданным учётным записям.** Самостоятельная регистрация выключена: пользователей создаёт администратор.
- **Построчный доступ** (в Supabase это называется RLS — Row Level Security). Для каждой записи база проверяет, кто запрашивает. Исполнителю она отдаёт только его задачи и только те объекты, где у него есть задачи. Чужих задач для него как будто не существует.
- **Смена статуса только по правилам.** Изменить статус можно одним способом — через специальную функцию в базе. Она проверяет, разрешён ли такой переход и есть ли у этого человека на него право. Возврат на доработку без комментария не пройдёт.
- **Историю нельзя подделать.** Записи истории создаёт сама база в момент смены статуса. Пользователь, в том числе постановщик, не может добавить, изменить или удалить запись. Время и автора база подставляет сама.
- **Секретные ключи не попадают в браузер.** Интерфейс работает с открытым ключом, который даёт только права обычного пользователя. Служебный ключ с полными правами в приложении не используется.

Правила проверены автоматическими тестами: 70 сценариев «а что если исполнитель попробует…».

**Что не может сделать исполнитель:**

- увидеть чужие задачи, их историю и объекты, где у него нет задач;
- создать, изменить или удалить объект или задачу (в том числе свою);
- принять задачу или вернуть её на доработку;
- перескочить статус (например, из «Новая» сразу в «Принята») или вернуть задачу назад;
- изменить или удалить историю, подставить в неё другое имя или дату;
- поменять себе роль на «Постановщик».
