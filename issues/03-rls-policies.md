# 03. RLS: права доступа постановщика и исполнителя

**Метка:** `security`  
**Статус:** выполнен

Включить RLS на всех таблицах и описать политики. Правила должны работать при прямых запросах к API в обход интерфейса.

- [x] Хелпер `is_manager()` (security definer, фиксированный `search_path`)
- [x] `profiles`: пользователь читает свой профиль; постановщик — все; исполнитель видит только профили, нужные для отображения; менять роль через API нельзя
- [x] `objects`: постановщик — полный CRUD; исполнитель — только чтение объектов, где у него есть задачи
- [x] `tasks`: постановщик — полный CRUD; исполнитель — чтение только своих задач, прямой `update` запрещён (смена статуса только через функцию смены статуса)
- [x] `task_status_history`: чтение для тех, кто видит задачу; `insert/update/delete` через API запрещены всем
- [x] Отозвать лишние права у `anon`

**Готово, когда:** исполнитель через supabase-js не может прочитать или изменить чужую задачу и чужой объект.
