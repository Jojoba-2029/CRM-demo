# 04. Переходы статусов задачи на стороне БД

**Метка:** `security`  
**Статус:** выполнен

Машина состояний задачи проверяется в базе: запрещённый переход не проходит даже при ручном запросе.

| Из           | В            | Кто                     | Условие                |
| ------------ | ------------ | ----------------------- | ---------------------- |
| —            | Новая        | постановщик             | при создании           |
| Новая        | В работе     | назначенный исполнитель |                        |
| В работе     | На проверке  | назначенный исполнитель |                        |
| На проверке  | Принята      | постановщик             |                        |
| На проверке  | На доработке | постановщик             | комментарий обязателен |
| На доработке | В работе     | назначенный исполнитель |                        |

Другие переходы запрещены.

- [x] RPC `change_task_status(task_id, new_status, comment)` (security definer): проверка роли, исполнителя и допустимости перехода
- [x] Возврат на доработку без непустого комментария — ошибка
- [x] Новая задача всегда создаётся в статусе `new`; статус нельзя поменять обычным `update` в обход функции (в том числе постановщику)
- [x] Понятные тексты ошибок для фронтенда
- [x] Решить и описать: можно ли переназначать исполнителя и редактировать задачу после «Принята»

**Готово, когда:** все запрещённые переходы возвращают ошибку при вызове из API.
